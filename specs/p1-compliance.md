### B1 升级 — 进货单增加批次字段

**进货明细新增必填字段**

| 字段 | 类型 | 说明 |
|------|------|------|
| 批号 | String(50) | ✅ 必填，农药追溯核心标识 |
| 生产日期 | Date | ✅ 必填 |
| 有效期至 | Date | ✅ 必填，自动计算效期预警 |

**保存逻辑升级**
- 保存进货单时，除了更新 `inventory` 表，同步写入 `inventory_batch`：

```python
# 伪代码
for item in purchase_items:
    # 1. 更新 inventory 总库存
    inv = get_or_create_inventory(item.product_id, warehouse_id)
    inv.quantity += item.quantity
    inv.available_quantity += item.quantity
    # 重新计算移动加权平均成本
    inv.cost_price = (inv.quantity_old * inv.cost_price_old + item.quantity * item.unit_price) / inv.quantity
    
    # 2. 写入批次库存
    batch = InventoryBatch(
        product_id=item.product_id,
        warehouse_id=warehouse_id,
        batch_no=item.batch_no,
        quantity=item.quantity,
        available_quantity=item.quantity,
        prod_date=item.prod_date,
        expiry_date=item.expiry_date,
        purchase_item_id=item.id
    )
    db.add(batch)
```

- 批号在同一个商品内必须唯一（进货时校验）

### C3 — 限制农药实名销售

**触发条件**
- 商品 `is_restricted == True`（由毒性=高毒/剧毒自动判定）

**弹窗采集字段**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 购买人姓名 | String(50) | ✅ | — |
| 身份证号 | String(18) | ✅ | 前端校验格式 |
| 联系电话 | String(20) | ✅ | — |
| 用途 (防治对象) | String(200) | ✅ | 如"防治蚜虫" |
| 使用作物 | String(100) | ✅ | 如"小麦" |
| 购买数量 | Float | ✅ | 受上限约束 |

**购买上限**
- `product` 表新增字段 `restricted_max_quantity` (Float, 默认 0=不限)
- 用户填写的数量 > 上限时 → 阻断并提示"该限制农药单次最多购买 X 瓶"

**数据写入**
- 写入 `restricted_sale` 表，关联 `sale_order_id`
- 该表无 `is_active` 字段，无 `DELETE` 路由，无 `PUT` 路由（不可修改/不可删除）

**前端交互**
```
1. 购物车中有限制农药 → 点击"确认开单"
2. 弹出 modal，采集实名信息
3. 校验通过 → 一起提交创建 SaleOrder + RestrictedSale
4. 校验不通过 → 停留在 modal，红色提示
```

### F3 — 红冲/冲正机制

**不可修改/不可删除**
- 进货单和销售单页面不显示"编辑"和"删除"按钮（创建后只读）
- 后端对应的 PUT/DELETE 路由也一并删除

**红冲按钮**
- 单据详情页 → "红冲"按钮
- 点击 → 确认弹窗"确定冲正该单据？此操作不可撤销"

**红冲逻辑**
1. 原单据 `is_reversed = True`
2. 创建新单据（同类型），所有 quantity 和 amount 取反：
   - 进货单红冲 → 库存扣减
   - 销售单红冲 → 库存回退
3. 新单据 order_no = 原单号 + "-REV"
4. 如涉及批次，红冲时回退对应批次库存
